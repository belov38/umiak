# Roadmap: areas for brainstorm

S17 (Ilia, 2026-11-03): S9/S10 now expose one Windows 11 template, `windows` with desktop on VM 595; `windows-desktop` remains a compatibility alias. VM 598 was retired in the catalog and deleted on 2026-11-04 with Ilia's approval. See [S17](specs/s17-windows-single.md). Earlier S9/S10 rows below retain historical build evidence.

Each area is a separate T3 Code thread (independent areas run in parallel, each in its own git worktree and branch): brainstorm → spec in `docs/specs/` → agreement with the user. Once the spec is agreed, the brainstorm thread is closed (settled), implementation goes in a separate thread on branch `sN-impl` (plan in `docs/plans/`), and master merges the branches into main. Architecture: `docs/architecture.md`.

PoC limits on `pve`: VMIDs from 500, at most 8 GB RAM in total, storage `local-lvm`. Allowed to create a user, token, pool, and an SDN Simple zone + VNet. Do not touch existing VMs, LXCs, and `vmbr0`.

Order: S1 → S2 → S3/S4 → S5 → S6 → S7 → S8 → S9 → S10 → S11. S12, S13, and S14 are phase 2; the MVP is deployed via docker compose (`deploy/compose`).

Ilia's decision 2026-10-29: sandbox creation time is not optimized, up to ~1 min is acceptable. A warm pool is not part of the MVP: Linux is created by a cold clone (~12 s), `failFast` / `pool_exhausted` (S6, S7) are not implemented, the pool remains a phase 2 task. Windows (S9) and `linux-desktop` (S10) also have no idle pools. For Windows up to 5 min is acceptable, 2–3 min is good: create takes the S9 cold path (template clone + sysprep specialize on first boot), the vTPM + `suspend --todisk` spike is not needed.

Implementation acceptance: master does not merge an `sN-impl` branch on the implementer's report alone. An independent test subagent builds, runs linters and tests, and checks behavior on `pve`; a separate thread fixes what it finds, after which the check is repeated.

Windows fork and saved snapshot (Ilia's decision 2026-11-01, branch `win-force-stop` in main): only from a cleanly stopped VM. A running Windows without the flag — `409 snapshot_requires_stop` with a `forceStop: true` / `--force-stop` hint; with the flag — graceful stop (Windows up to 300 s) → `powered_off` snapshot → source start → fork. Shutdown timeout — `shutdown_timeout` without a snapshot; once the snapshot is ready, the fork is not rolled back. `machines.clean_stop` (migration `0208`): Windows without a clean shutdown — `snapshot_requires_clean_stop`, Linux — `consistency: crash`. Follow-ups (non-blocking): the refusal for a stopped Windows without `clean_stop` arrives asynchronously (fork `202` → `fork_failed`), worth checking in the API; after `snapshotTaken` there is no upper bound on retries of the final transaction; the Windows template verify on a 598 rebuild may fail on a hung VSS thaw (`ThawFailedError` does not lead to the crash fallback) — check on rebuild; the CLI `--wait` default of 5 min is less than the worst Windows stop (7 min).

Follow-ups after S10 acceptance (2026-11-01): W1-B — on Windows the websocket viewer is sometimes black (2 of 5 runs, Sunshine sends an IDR once per second; the `web-server.log` diagnostics are captured too late); a 3–6 s window after unblock when a ticket with the block epoch is still being exchanged (`unblockSandbox` without NOTIFY, the exchange does not check `policy_revoked`); under load the deferred Windows reboot for the rename fires after claim (`winboot.go`); the TURN watchdog does not check the address on `lo`; sending a relay to a forbidden port kills its own allocation (to be documented); TURN-TLS on 443 and a dedicated address — S12 (phase 2).

S10 follow-ups closed (merge `s10-followups`, 2026-11-01). W1-B was a race in Sunshine: `recvThread` stores one sender address per video and audio socket, and simultaneous pings could record the audio socket as the video address. `windows-desktop` ships moonlight-web v3.0.1 with `ping-order.patch` (audio waits for the first video packet). Unblock sends NOTIFY while a `policy_revoked` desktop is considered blocked. The Windows agent does not become ready until the rename reboot (`rebootBoot`) has happened. The TURN watchdog checks the address on `lo`. Remaining (low): `POST /links` and `open` during the `policy_revoked` window issue a link that later yields 401 (better to refuse immediately); the moonlight-web build is not reproducible (Rust and mingw images by tag, no `--locked`, no expected sha in git); the "no reboot after claim" check in `e2e-desktop` only looks at 1–2 min; the Sunshine fix could be sent upstream (not sent, Ilia's decision); `TestQuiesceBudget` flake under load. Template 598 was rebuilt with the reboot fix (`win598-rebuild`, `windows 20261101.1`, S9 §24.10).
