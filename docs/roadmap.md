# Roadmap: области для brainstorm

Каждая область — отдельный тред T3 Code (независимые области идут параллельно, каждая в своём git worktree и ветке): brainstorm → спецификация в `docs/specs/` → согласование с пользователем. После согласования спецификации brainstorm-тред закрывается (settle), реализация идёт в отдельном треде и ветке `sN-impl` (план в `docs/plans/`), master сливает ветки в main. Архитектура: `docs/architecture.md`.

Ограничения PoC на `pve`: VMID от 500, не больше 8 GB RAM на всё, хранилище `local-lvm`. Разрешено создать пользователя, токен, pool и SDN Simple zone + VNet. Существующие VM, LXC и `vmbr0` не трогать.

Решение Ильи 2026-10-29: время создания sandbox не оптимизируем, до ~1 min допустимо. Warm pool в MVP не входит: Linux создаётся холодным клоном (~12 s), `failFast` / `pool_exhausted` (S6, S7) не реализуются, пул остаётся задачей фазы 2. Windows (S9) и `linux-desktop` (S10) тоже без спящих пулов. Для Windows до 5 min допустимо, 2–3 min — хорошо: create идёт холодным путём S9 (клон шаблона + sysprep specialize при первой загрузке), спайк vTPM + `suspend --todisk` не нужен.

Приёмка реализации: master не сливает ветку `sN-impl` только по отчёту исполнителя. Независимый тестовый субагент собирает, прогоняет линтеры и тесты и проверяет поведение на `pve`; найденное исправляет отдельный тред, после чего проверка повторяется.

Dev-стенд control plane (решение 2026-10-30): unprivileged LXC CT 590 на `pve` (`vmbr0`, 3 GB сверх лимита sandbox), в нём docker compose; адрес CT в IPSet `sbx-gateway`. В проде control plane один на платформу (Kubernetes), а на нодах Proxmox в `sbx-gateway` — адрес балансировщика gateway. Имена dev-стенда (2026-10-30): агенты — `tunnel.192-168-68-90.sslip.io` (LAN, dev CA, который пинит агент), превью — `*.sbx.100-64-10-7.sslip.io` (tailnet, dev CA), дашборд, api и Keycloak — Tailscale Serve на `sbx-dev-cp.<tailnet>.ts.net` (:8443, :10000, Let's Encrypt); всё в `infra/dev-cp/` (README «Names and TLS»).

Миграции БД (`db/migrations/NNNN_*.sql`, решение master 2026-10-31): номера зарезервированы по областям, чтобы параллельные треки не сталкивались. `0100–0199` — S2 (`tunnel`); `0200–0299` — runtime: S6 и изменения таблиц runtime из S7 (`0204`, `0205`) и S8 (`0206_sandbox_block_meta.sql`); `0300–0399` — S7; `0400–0499` — S8 (`0400_environments_runtime.sql`: environments команд переезжают из `identity` в `runtime`). Исключение по решению master: колонки `reason` и `output_truncated` таблицы S6 `runtime.commands` из приёмочных правок S7 лежат в `0304_command_output.sql` (диапазон S7), с комментарием в миграции. Новые области берут свой диапазон здесь, прежде чем добавлять миграции.

Сквозной тест на dev-стенде (2026-10-31, в main): весь стек MVP на CT 590, сценарий `infra/dev-cp/e2e.sh` с Mac (login, create, exec, PTY, cp, превью token/sso, ssh, fork, snapshot, stop/resume, idle-stop, delete, оба SDK) — 20/20 PASS, независимая приёмка повторила прогон. Вход для Ильи — `infra/dev-cp/QUICKSTART.md`. Найденное в E2E закрыто веткой `fix-resume-sshca` (в main): worker при каждом resume/recover/reprovision заново отправляет агенту ключи SSH user CA, `sbx logs -f` выходит с кодом команды, `snapshot save --wait --json` пишет события `accepted`/`ready`/`error`; `create --from <snapshot>` переносит только диск, без env и секретов (S7 §8.3).

Доработки после приёмки S11 (2026-10-31, не блокируют MVP): API (S7) отдаёт сообщения агента без очистки (MCP их чистит сам); `exec_list` после kill ещё ~10 s показывает `running`; в S12 поду `mcp` нужен `preStop` sleep (по SIGTERM основной порт сразу закрывается).

Первая сборка для Ильи: весь стек MVP поднимается локально через docker compose (`deploy/compose/`): Postgres, api, worker, gateway, web, Keycloak, oauth2-proxy; Proxmox — `pve`. Каждый тред реализации добавляет туда свой сервис.
