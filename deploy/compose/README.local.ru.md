# Umiak дома: один пользователь, без Keycloak

В этом режиме любой клиент из разрешённой сети получает полный контроль над VM,
личную команду и права оператора. Не публикуйте порты в Интернет.

1. Настройте Proxmox и секреты по [основному README](README.md). Нужны PVE URL,
   token ID и файл токена, доверенный CA Proxmox и SSH-ключ node-agent. Шаблоны
   должны быть уже зарегистрированы; `none` не меняет протокол гостевого агента.
2. Создайте `deploy/compose/.env` (не коммитить), например:

   ```dotenv
   UMIAK_PVE_URL=https://192.168.1.2:8006
   UMIAK_PVE_TLS_NAME=pve
   UMIAK_NODE_SSH_HOST=192.168.1.2
   UMIAK_PVE_TOKEN_ID=umiak@pve!home
   UMIAK_PVE_SECRETS_DIR=/absolute/path/to/umiak-secrets
   UMIAK_APP_ORIGIN=http://192.168.1.10:4180
   UMIAK_API_PUBLIC_URL=http://192.168.1.10:8080
   UMIAK_MCP_PUBLIC_URL=http://192.168.1.10:8090/mcp
   UMIAK_MCP_ALLOWED_HOSTS=192.168.1.10:8090
   UMIAK_LOCAL_BIND=192.168.1.10
   UMIAK_LOCAL_DENIED_CIDRS=192.168.1.2/32,10.88.0.0/24
   ```

   Здесь `192.168.1.10` — LAN IP компьютера с Docker. По умолчанию разрешены
   loopback, RFC1918 и IPv6 ULA. Для Linux с сохранённым IP клиента можно сузить allowlist до своей сети.
   Пустой список недопустим. Docker Desktop может подменять IP клиента своим
   gateway: проверяйте фактический адрес и границу доверия на вашем хосте.
3. Запустите из корня репозитория:

   ```sh
   docker compose -f deploy/compose/compose.yaml -f deploy/compose/local.yaml up -d --build
   ```

   Это отдельный проект `umiak-local`; не включайте профиль `excluded-oidc`.
   Keycloak и oauth2-proxy не запускаются. Откройте
   `http://192.168.1.10:4180/app` или `/admin`. Вход/выход не нужен.
   Не публикуйте напрямую порт 3000 web: ingress проверяет адрес клиента и
   перезаписывает заголовки; Origin/CSRF проверки продолжают действовать.
4. CLI:

   ```sh
   umiak login --api-url http://192.168.1.10:8080
   umiak create --template linux --size 2gb --wait
   # Подставьте slug, напечатанный create:
   umiak exec <slug> -- uname -a
   umiak rm <slug> --yes
   ```

   Профиль не содержит OAuth-токенов. SDK можно использовать без ключа, MCP —
   по `http://192.168.1.10:8090/mcp` или `umiak mcp`. Командные API-ключи
   продолжают работать со своими ограничениями.

Превью используют прежний HTTPS wildcard/sslip.io и CA; `token` и `public`
работают как прежде. `sso` отвечает 403: выберите `token` или `public`.
Туннель гостей остаётся WSS с закреплённым CA. Для уже собранных шаблонов
сохраните доверенный ими CA и доступность адреса туннеля, указанного в их
конфигурации/параметрах машины. Не генерируйте новый CA вместо закреплённого.
На dev-стенде это CT590:443; второй стек на другом порту не заменяет его
без изменения сети. Поэтому local compose сам по себе не переносит существующие
шаблоны на другой gateway и не меняет firewall/SDN.

Для остановки используйте те же два `-f` с `down` (без `-v`, если нужны данные).
Возвращение к OIDC — обычный compose без local.yaml и с отдельным именем проекта;
не направляйте оба режима на одну production БД одновременно.

Этот override рассчитан на прямое подключение из LAN. Не ставьте перед local
HTTP ingress внешний reverse proxy: иначе socket peer будет адресом прокси,
а не клиента. Для отдельного API/MCP используйте явные trusted proxy CIDRs,
если публикуете их через прокси; доверяйте только адресам, которые перезаписывают
X-Forwarded-For. Никогда не добавляйте внешний proxy CIDR в список разрешённых
клиентов вместо проверки реального адреса.

Для туннеля доступны `UMIAK_TUNNEL_URL` (worker передаёт его через SMBIOS),
`UMIAK_TUNNEL_HOST`, `UMIAK_PREVIEW_DOMAIN`, `UMIAK_SSH_HOST` и
`GATEWAY_HTTPS_PORT` (обычно 443 для существующих dev guests). Имена должны
совпадать с сертификатами в `deploy/compose/secrets/gateway`, подписанными CA,
которому уже доверяют шаблоны. Этот режим не снимает сетевые ограничения PVE:
сначала обеспечьте существующий разрешённый путь гостей к gateway.

По умолчанию bind — **127.0.0.1**, доступ только с Docker-хоста. Для LAN укажите
его конкретный адрес, как в примере. На Docker Desktop peer обычно `192.168.65.1`,
а при loopback bind может быть `172.29.115.1`: все клиенты выглядят одинаково.
Allowlist только `192.168.1.0/24` там заблокирует и владельца. На Linux Docker
LAN IPv4 обычно сохраняется, но localhost, IPv6 и userland-proxy могут показывать
адрес bridge. Первые десять запросов API/MCP/ingress логируют наблюдаемый адрес.
Реальная граница при NAT — bind и firewall хоста; не доверяйте заголовкам клиента.

`UMIAK_LOCAL_DENIED_CIDRS` имеет приоритет. По умолчанию запрещена sandbox-сеть
`10.88.0.0/24`; задайте свою, если она отличается. API дополнительно запрещает
буквальные IP `UMIAK_PVE_URL` и `UMIAK_NODE_SSH_HOST`. Для всех ingress явно
добавьте адрес SNAT узла (как `192.168.1.2/32` в примере). Sandbox-сеть и SNAT
узла не должны достигать app/API/MCP портов: сохраните гостевую сетевую изоляцию.
Не разрешайте адрес NAT, если за ним находятся и доверенные клиенты, и sandbox.
Пустой allowlist — ошибка запуска; `/0` вызывает предупреждение. `/v1/docs`
в none отключён, чтобы сторонний CDN-скрипт не получил полный доступ к origin.
